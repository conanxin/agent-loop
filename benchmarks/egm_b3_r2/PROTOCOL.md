# EGM-R2 Gate B3-R2｜真实源码审查评分协议（预先登记）

研究日期：2026-10-27，北京时间。目的：在上一轮植入简单冲突的测试未观察到 Goldfish 额外收益之后，开展未经人工植入问题的真实文档与源码审查。

## 实验对象与冻结方式

从 Git 提交 `231290845a4117ba7e05ac5226b802b4faf11045` 导出三个固定审查包：

1. **protocol-implementation**：文档的状态转移、`agent-loop-relay` 的状态行为与 `agent-loop-set-state`。
2. **p6-evidence-integrity**：原文证据封存、父子任务 SHA 来源、双 Reviewer 复核。
3. **p9-public-mcp-boundary**：受限 MCP 工具、公开 Token 作用域与任务范围约束。

没有人为植入错误或“正确答案”，审查包仅从真实文件抽取原始行并标示原路径/原行号。相关包 SHA 和片段清单在 `manifest.json`；原始文件及完整代码可能还有未纳入审查包的逻辑，这一点是评分时必须尊重的限制。

## 对照与重复

相同 MiniMax M3.1 Flash 模型、相同输入包、相同 JSON 输出要求，普通审查与 Goldfish 风格审查每种跑两次：3 包 × 2 策略 × 2 重复 = 最多12次。对每份包与不同重复交错安排策略顺序；所有运行采用独立 headless `agent exec`、无旧会话、`contextInjection=never`、`tools.deny=["*"]`、`tools.toolSearch=false`，不请求外部网络、Shell 或文件工具。

只改变审查方法提示词，模型、输出上限、数据边界和预算一致。**本实验测单次 Goldfish 风格的独立审查，而非官方 EGM 完整五阶段联动工作流。**

## 评分规则（在看模型输出前制定）

- 有效交付：CLI 返回成功，能解析严格 JSON，来源 SHA 匹配，且有完整会话回执。
- **SUPPORTED**：审查主张在提供的原文件、源码或受限代码行为中有直接而具体的证据，提出可复核的错误/风险及影响；引用位置必须能检索且语义上支持结论。
- **PARTIAL/UNVERIFIED**：具备合理风险但缺少必要上下文、依赖未展示的函数、需要运行复现才能判定。
- **UNSUPPORTED**：事实错误、虚构 API、错误引用、将“未在摘要中看到”当成“整个系统不存在”、或没有实际问题仅给笼统建议。
- **DUPLICATE**：同一包中多个报告指向同一可执行修复点的重复论点，按一个有效问题计。
- “Goldfish 额外发现”需与同一包的两次普通审查比较：只有经独立裁定为 SUPPORTED 且不与普通审查可复核问题重复的，才记候选新增发现。不得单纯按 findings 条数判胜。
- 由独立模型或独立审查者判断时，必须将输出去除 baseline/Goldfish、执行顺序和重复次数标签；审查者仍需依照原始代码证据，而不是凭模型语气选择优劣。
- 未由独立审查者审核的输出暂不计为已确认真阳性，也不能随意称作假阳性。
- 观测事实的来源、引用行号存在与引用的语义支持分开记录。
- 交付失败、超时、工具调用及无效 JSON 均按原始终态保留，严禁覆盖后重跑却当成第一次。
- Token 使用量、模型 API 调用、缓存及时间可分别统计；实际美元费用无可靠账单则填“未核实”，不得由 0 美元估算断言免费。
- 报告各策略的可交付率、证据支持问题数、重复检出和成本；3 包 × 2 次是**小样本探索**，禁止宣传显著的普适质量优势。

## 明确的决策门槛

在本次没有发现稳定额外高价值问题之前，不把 Goldfish 默认路由给所有任务；仍维持单 Agent 日常优先。若发现新增 SUPPORTED 且实际可修复的风险，优先在独立人工确认后选择性为跨主机/安全敏感/复杂设计触发 Goldfish，不能直接自动给新 Agent 开通修改生产代码的权限。

## 安全边界

只读当前自有公开仓库版本；不修改已有 CX-PAN Hub/Worker、Gateway、OAuth、公网 MCP，也不碰 NAS、本地其他磁盘与生产仓库敏感配置。固定审查包可存入 Git，真实模型原始输出及会话 SQLite 在实验私有目录，Notion 只记录有证据的结论与统计。
